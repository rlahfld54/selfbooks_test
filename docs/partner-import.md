# 거래처 엑셀 등록 UI

## 2026-11-16 실제 DB 연동 — 현재 동작

이 절은 아래의 과거 구현 중 **탭 메모리 전용/DB 미저장/새로고침 초기화** 설명을 대체한다. 사용자 요청에 따라 `tax_offices`를 거래처 조회 및 엑셀 저장 테이블로 사용한다. `business_partners`는 만들지 않는다.

- `/clients`에서 요청한 15개 컬럼을 순서대로 표시한다. 20행 페이지 나누기·가로 스크롤·정렬·업체명/번호/코드 검색·상세 패널을 제공한다. 표의 (*)는 제공된 양식 표시이며 기존의 누락값 확인요망 등록 정책을 강화하지 않는다.
- `GET /api/partners`: 서버 설정 사무소 자체(`id`)와 그 사무소가 등록한 행(`managed_by_office_id`)을 반환한다. `POST /api/partners/import`: `{ batchId: UUID, rows: [{ sourceLine, information, importIssues }] }`를 받는다. 인증된 관리자 및 서버 사무소 범위를 사용하며 로컬 개발 모드에서만 동작한다. 회사·사용자 ID를 본문에서 받지 않는다. 로그인 소속을 자동 생성하지 않는다.
- POST는 매개변수 바인딩과 `jsonb_to_recordset`으로 한 번의 INSERT를 실행한다. 한 트랜잭션에서 전부 저장하거나 롤백한다. 사무소별 트랜잭션 잠금 아래 서버도 중복·번호·이메일 등을 재검증한다. UI의 파일 수식 경고 등도 보존한다.
- 업종별 중복 번호 허용을 위해 `tax_offices_business_registration_number_key`를 제거했다(사용자 승인). 번호·업종코드·업태·업종이 모두 같은 행은 기존처럼 확인요망으로 저장한다. 자연키 UNIQUE로 오류 포함 등록을 막지 않는다. 기존 `office_members.office_id`는 UUID를 참조하므로 유지된다.
- 원문은 `import_information`, 오류는 `import_issues`, 원본 행은 `import_source_line`에 저장한다. 기존 번호 CHECK는 유지하므로 형식이 잘못된 번호의 정규 컬럼은 NULL로 저장하고 원문은 JSON에서 조회한다. 빈 업체명은 정규 컬럼에 '(거래처명 없음)'으로 저장하며 원문은 빈 값으로 유지한다. 업체명·대표자명 100자, 최대 5,000행/100열, 값 1,000자, HTTP 본문 10MB를 넘으면 전체 요청을 거부한다.
- `import_batch_id`와 요청 해시를 보존한다. 같은 업로드의 재시도는 기존 결과를 반환하고, 같은 ID로 다른 내용을 보내면 409를 반환한다. 저장 실패 시 모달과 파일을 유지하며 재시도한다. 파일·시트를 바꾸면 새 배치가 된다. 파일을 다시 선택하여 등록하는 것은 새로운 업로드이므로 중복 경고와 함께 추가 가능하다.
- 원본 사무소 `phone`/`email`은 대표 연락처이므로 담당자 개인 연락처로 전용하지 않는다. 추가 담당자 컬럼에 별도 저장한다. `business_type`은 기존처럼 **업태**이며 **사업자 구분**은 `business_kind`다.

마이그레이션: `backend/migrations/007_tax_office_partners.sql`, 실행: `npm --prefix backend run db:migrate:partners`. 연결된 Supabase에 적용 완료했으며 기존 1행을 유지했다. RLS와 브라우저 직접 접근 차단을 유지한다. 신규 Nuxt API는 도입하지 않았다.

검증: 백엔드 단위 26개·프런트엔드 단위 51개, 양쪽 타입 검사/빌드 통과. 실제 Supabase 통합 테스트(`npm --prefix backend run test:integration:partners`)에서 15개 항목 왕복, 업종별 중복, 확인요망, 원문, 재시도, 원자성, 사무소 격리를 확인했다. 테스트 데이터는 최종 롤백한다. 브라우저에서는 Mock API를 사용해 업로드·저장 실패 재시도·15컬럼·상세·탭·390px·새로고침 유지·hydration을 확인했으며 작업 공간 회귀 8개 시나리오도 통과했다. 실제 사용자 인증 세션으로 브라우저에서 저장하는 종단 검증은 수행하지 않았다.

주요 변경 파일: `backend/src/routes/partners.ts`, `backend/src/services/partners-{repository,validation}.ts`, `backend/src/db/migrate-partners.ts`, `backend/src/app.ts`, 거래처 `PartnerListView.vue`, `PartnerImportDialog.vue`, `DemoPartnerDetails.vue`, `services/partnersApi.ts`, `usePartnerListSession.ts`, 공통 `DataTable.vue` 및 관련 테스트. 기존 수정/삭제 작업에는 관여하지 않았다.

## 이전 메모리 전용 구현 기록

2026-11-16: `/clients`의 **엑셀 등록**에서 XLS/XLSX(최대 5MB, 시트별 데이터 5,000행/100열)를 선택하고 시트·미리보기·검사 결과를 확인한 뒤 전체를 한 번에 반영한다. 원본 파일은 수정하거나 서버에 전송하지 않는다.

- 첫 행은 헤더다. 첨부 양식의 15개 항목을 매핑하고 알 수 없는 추가 컬럼도 상세에 보존한다. 사업자 구분은 원본 헤더에서 확인한 1 개인/2 법인만 해석한다. 사용자명은 담당자명이며 로그인 계정을 생성하지 않는다.
- 필수 헤더는 사업자등록번호, 사업자 구분, 법인등록번호, 업체 명, 대표자 명, 업종코드, 업태, 업종, 우편번호, 기본주소의 10개다. 나머지 컬럼은 생략하거나 값을 비워도 등록 가능하며 누락 경고/확인을 요구하지 않는다. 필수 헤더와 필수 값 검사는 구분하며 법인등록번호의 빈 값은 허용한다. 거래처명·사업자등록번호·사업자 구분의 값 검증은 유지한다. 사업자번호 10자리, 법인번호 입력 시 13자리, 이메일 형식, 수식, 중복 헤더 및 코드 중복 및 사업자등록번호·업종코드·업태·업종 조합 중복을 검사한다. 같은 사업자번호여도 업종코드·업태·업종 중 하나가 다르면 정상 등록한다. 이 기준은 파일 내부와 기존 목록에 동일하게 적용한다. 사업자번호의 하이픈/공백과 각 업종 항목 앞뒤 공백은 비교 시 제외한다. 사업자번호 실재 여부나 세무상 유효성은 검증하지 않는다.
- 대표자명 누락과 우편번호 형식은 확인요망이다. 오류·경고는 등록을 막지 않는다. 오류 행만 보기 필터와 필터 기준 페이지 나누기를 제공하며, 필터와 무관하게 전체 행을 등록한다. 등록 후 오류·경고 사유와 원본 행 번호를 상세에 보존하고 확인요망으로 표시한다. 중복 코드도 원문을 유지하되 내부 행 ID는 고유하게 발급한다. 손상 파일, 필수 헤더 누락/중복, 용량·행수 제한은 읽기 단계에서 계속 거부한다. 기존 거래처 덮어쓰기는 없다.
- 코드가 없으면 기존·업로드 코드와 충돌하지 않는 IMP 일련 코드를 부여한다. 연락처·코드·우편번호는 텍스트로 취급한다. 엑셀에 숫자로 저장되어 이미 유실된 선행 0은 추정 복구하지 않는다.
- 목록 검색·상세에서 가져온 정보를 확인한다. 데이터는 거래처 탭 메모리에만 유지되며 탭 이동 후 복원된다. 새로고침/탭 닫기/회사 변경 시 폐기되고 기존 미저장 보호를 적용한다. localStorage에 거래처 정보를 저장하지 않는다.
- 실제 business_partners DB 및 매입매출전표 마스터와 연결하지 않는다. 온보딩의 별도 거래처 시안은 이번 대상이 아니다.

## 추가 권장 항목 및 미확정 사항

거래처 코드, 매출/매입/겸용 구분, 사용 여부, 세금계산서 수신 이메일, 메모를 우선 권장한다. 결제조건·담당 직원·은행/계좌/예금주는 업무 필요에 따라 후속 확정한다. 개인 이메일과 세금계산서 수신 이메일은 분리한다. 선택 추가 항목은 원문을 보존하며 미확정 코드 의미를 추측하지 않는다.

DB 연동 시 회사 범위는 서버에서 주입하고 고유 키, 본점/지점 구분, 중복 병합 정책, 일괄 저장 트랜잭션, 감사 이력 및 실제 저장 API를 별도로 설계해야 한다. 내부 UUID·회사 ID·생성/수정 일시·작업자는 사용자 엑셀 입력 항목이 아니다.

파서는 [SheetJS 공식 배포](https://docs.sheetjs.com/docs/getting-started/installation/frameworks/)의 0.20.3에 고정한다. 신규 Nuxt API는 도입하지 않았다.
