# Accounting Pro — 공통 UI 시스템 구현 지시서 v1.0

## 1. 프로젝트 목표

Accounting Pro는 세무사 사무실과 일반 기업의 회계 담당자가 사용하는 웹 기반 회계·ERP 프로그램이다.

첨부한 디자인 참고 이미지와 아래 명세를 기준으로 공통 UI 시스템을 구현한다.

디자인 방향은 **Modern SaaS + Light Theme**이다.

중요한 목표는 다음과 같다.

- 참고 이미지의 파란색 Sidebar, 흰색 콘텐츠, 깔끔한 대시보드 디자인을 최대한 재현한다.
- 모든 화면에서 동일한 디자인 토큰과 공통 컴포넌트를 사용한다.
- 장시간 사용하는 회계 프로그램이므로 정보 밀도와 키보드 사용성을 중요하게 고려한다.
- 이후 회계관리, 매입매출관리, 세무신고 등의 업무 화면을 쉽게 추가할 수 있도록 확장 가능하게 설계한다.
- 현재 단계에서는 공통 UI와 레이아웃을 구현하며 실제 회계 업무 로직은 구현하지 않는다.

참고 이미지의 상단 디자인 시스템 설명 영역은 실제 프로그램 화면이 아니다. 하단의 대시보드와 Sidebar 디자인을 주요 시각적 기준으로 활용한다.

참고 이미지에 있는 자유로운 다중 창 방식은 구현하지 않는다. **업무 탭 + 오른쪽 상세 패널** 구조로 대체한다.

## 2. 기존 프로젝트 확인

코드를 수정하기 전에 반드시 다음을 확인한다.

1. 현재 프로젝트의 폴더 구조와 프론트엔드 프레임워크
2. package.json 및 설치된 라이브러리
3. 기존 라우터, 상태 관리 방식, 스타일링 방식
4. 현재 구현된 페이지와 공통 컴포넌트
5. 기존 코드의 네이밍 규칙과 파일 구성 방식

기존 기술 스택이 있다면 그대로 활용한다.

기존 구현과 충돌하지 않는 범위에서 컴포넌트 기반 구조를 설계하고, 같은 역할의 UI 라이브러리를 중복 설치하지 않는다.

설치되지 않은 프레임워크나 상태 관리 라이브러리를 임의로 추가하기 전에 필요성을 설명한다.

전역 디자인 토큰을 정의하고 모든 컴포넌트가 이를 참조하도록 한다.

### Colors

- Primary: #2457C5
- Primary Hover: #1D46A3
- Primary Light: #EAF1FF
- Background: #F5F7FA
- Surface: #FFFFFF
- Text Primary: #1E293B
- Text Secondary: #64748B
- Border: #DCE2EA
- Success: #16A34A
- Warning: #D97706
- Danger: #DC2626

Sidebar는 참고 이미지처럼 딥블루 배경으로 구현한다. Sidebar 전용 배경색은 #21468C를 기본으로 하며 활성 메뉴에는 Primary 계열 색상을 적용한다.

### Typography

- Font: Pretendard, sans-serif
- Page Title: 24px / 600
- Section Title: 16~18px / 600
- Body: 14px / 400
- Table: 13px / 400
- Caption: 12px / 400

금액은 tabular-nums를 사용하고 우측 정렬한다.

### Spacing

기본 간격 단위는 4px로 한다.

- 4px: 아이콘과 작은 요소
- 8px: 작은 요소 사이
- 12px: 폼 요소 사이
- 16px: 카드 사이
- 20px: 카드 내부
- 24px: 페이지 외곽
- 32px: 큰 섹션 사이

### Radius

- Small: 6px
- Medium: 10px
- Large: 14px

과도한 그림자나 그라데이션은 피한다. Sidebar 및 주요 브랜드 요소를 제외하면 흰색 배경과 얇은 테두리를 기본으로 사용한다.

## 4. AppShell 레이아웃

모든 업무 페이지는 동일한 AppShell을 사용한다.

구성:

- Sidebar
- Header
- TabBar
- PageContent
- DetailPanel
- Global Modal / Toast 영역

### Sidebar

- 기본 폭: 220px
- 축소 폭: 64px
- 위치: 화면 왼쪽 고정
- 축소 상태에서는 아이콘 중심으로 표시
- 확장 상태에서는 아이콘과 메뉴 텍스트 표시
- 하위 메뉴 펼치기/접기 지원
- 현재 활성 메뉴 강조
- 사용자별 Sidebar 상태 저장

메뉴 구조는 홈, 회계관리, 매입매출관리, 인사급여, 세무신고, 보고서, 환경설정으로 구성한다.

### Header

- 높이: 56px
- 회사 선택
- 현재 사용자 표시
- 알림 영역
- 화면 공통 기능 영역

### TabBar

- 높이: 40px
- 업무 탭 생성, 활성화, 닫기 지원
- 동일 업무 화면은 하나의 탭만 허용
- 열린 탭이 많아지면 가로 스크롤
- 활성 탭 강조
- 탭마다 독립적인 화면 상태 유지

홈은 기본 탭으로 제공한다.

### PageContent

- 기본 배경: #F5F7FA
- 페이지 기본 여백: 24px
- 1440px 미만에서는 여백 16px 적용 가능
- 업무 페이지는 가용 너비를 활용
- 데이터 테이블의 가로 스크롤은 테이블 내부에서 처리

### DetailPanel

- 오른쪽에 표시
- 기본 폭: 360px
- 조절 가능한 폭: 320~480px
- 패널을 열면 본문 영역의 가용 폭 감소
- 닫기 버튼 및 Escape 지원
- 탭별 독립 상태 관리
- 창 크기가 부족하면 오버레이 방식으로 전환
- 패널이 열리거나 닫혀도 입력 데이터 유지

업무 API 호출이나 전표 저장 로직을 기본 UI 컴포넌트에 직접 포함하지 않는다.

## 6. DataTable 규칙

DataTable은 조회 중심의 공통 목록 컴포넌트이다.

필수 기능:

- 헤더 고정
- 행 선택
- 정렬
- 페이지네이션
- 로딩 표시
- 데이터 없음 표시
- 컬럼 너비 정의
- 가로 스크롤
- 기본형/압축형 밀도 변경

크기:

- 헤더: 36px
- 기본형 행: 42px
- 압축형 행: 32px
- 텍스트: 13px

금액은 우측 정렬하고 천 단위 구분 기호를 표시한다.

전표 입력용 편집 그리드는 DataTable과 구분한다. VoucherGrid는 추후 업무 화면 구현 시 별도 컴포넌트로 개발한다.

## 7. Modal 및 검색 규격

### Modal 크기

- ConfirmDialog: 420px
- 일반 Modal: 480px
- SearchDialog: 640px
- Large Modal: 800px
- 최대 높이: 화면의 80%
- 모바일: 화면 너비에서 좌우 16px씩 제외

내용이 길면 모달 내부에서 스크롤한다.

### SearchDialog

- 계정과목 및 거래처 등의 값 선택에 사용
- 열리면 검색 입력창에 포커스
- 방향키로 검색 결과 이동
- Enter로 선택
- Escape로 닫기
- 선택 후 원래 입력 필드로 포커스 복귀

### SearchPanel

- 거래처 상세정보, 관련 전표, 증빙 등 조회용
- 업무 화면을 유지하면서 오른쪽에서 정보 조회
- SearchDialog와 공통 검색 로직을 재사용할 수 있도록 구성

## 8. 탭 및 회사 전환 상태 관리

### 탭 규칙

- 동일 업무 메뉴는 탭 하나만 허용
- 다시 클릭하면 기존 탭 활성화
- 탭 전환 시 입력 중인 화면 상태 유지
- 변경 사항이 없는 탭은 바로 닫기
- 미저장 데이터가 있는 탭은 닫기 전 경고
- 재접속 시 열려 있던 업무 탭과 마지막 활성 탭 복원

### 탭 복원

사용자 ID와 회사 ID를 기준으로 복원 상태를 관리한다.

조회 조건, 업무 탭 목록, 마지막 활성 탭은 복원할 수 있다.

미저장 전표의 실제 입력 데이터는 이번 버전에서 자동 복원하지 않는다. 단, 사용자가 변경 사항을 가진 채 탭을 닫으려 할 때는 경고한다.

브라우저 새로고침·종료 시에는 가능한 범위에서 beforeunload 경고를 적용하되 브라우저 동작상의 제한을 고려한다.

### 회사 전환

- 회사 변경 시 기존 업무 탭 확인
- 변경 사항이 있는 탭이 있으면 경고
- 사용자가 취소하면 기존 회사 유지
- 사용자가 전환을 승인하면 기존 업무 탭 정리
- 새 회사의 업무 컨텍스트로 화면 재구성
- 이전 회사 데이터가 새 회사 화면에 표시되지 않도록 처리

현재 인증 또는 회사 API가 없다면 실제 권한·회사 전환을 구현한 것처럼 처리하지 말고, 별도 샘플 상태로 UI 동작만 검증한다.

## 9. 사용자별 UI 설정

다음 항목을 저장한다.

- Sidebar 접기 상태
- 테이블 밀도
- 마지막 활성 탭
- 업무별 열린 탭 목록
- 필요 시 상세 패널 상태

초기 구현에서는 기존 프로젝트의 사용자 설정 저장 방식을 활용한다.

서버 기반 사용자 설정 시스템이 없다면 사용자별 네임스페이스를 가진 로컬 저장 방식을 사용할 수 있다.

민감한 회계 데이터, 비밀번호, 인증 토큰, 미저장 전표 내용은 UI 설정에 저장하지 않는다.

## 10. 반응형 규칙

### 1440px 이상
- 전체 데스크톱 레이아웃
- Sidebar 확장 가능
- DetailPanel 360px 기본

### 1024~1439px
- Sidebar 축소 지원
- 콘텐츠 여백 16px
- 테이블 가로 스크롤 허용

### 768~1023px
- Sidebar 기본 축소 표시
- 상세 패널은 오버레이 방식
- 탭 가로 스크롤

### 767px 이하
- Sidebar를 모바일 메뉴 형태로 전환
- 상세 패널을 전체 화면형으로 표시
- 테이블은 가로 스크롤
- 버튼 및 입력 영역의 터치 접근성 확보

실제 회계 작업은 데스크톱을 우선한다.

페이지 전체에서 불필요한 가로 스크롤이 발생하지 않도록 한다.

## 11. UI 데모 및 검증 화면

실제 백엔드 연동 없이도 공통 UI를 확인할 수 있도록 데모 화면을 제공한다.

다음 화면을 구성한다.

1. Home Dashboard
   - 오늘의 전표
   - 이번 달 매출/매입
   - 최근 처리 내역
   - 공지사항

2. 일반전표입력 레이아웃 샘플
   - 페이지 제목 및 툴바
   - 입력 필드
   - 읽기 전용 예시 데이터 테이블
   - 거래처 검색 팝업 호출
   - 상세 패널 열기/닫기

3. 거래처관리 샘플
   - 검색창
   - 테이블
   - 행 선택
   - 거래처 상세 패널

실제 회계 분개 처리, 데이터 저장 및 신고 로직은 구현하지 않는다.

## 12. 품질 및 접근성

- 아이콘은 기존 프로젝트 아이콘 체계로 통일
- 모든 입력창에 포커스 스타일 제공
- 모달에서 포커스 이동 및 복귀 지원
- 버튼에 적절한 disabled 상태 적용
- 오류 메시지는 입력 필드 근처 표시
- 키보드만으로 기본적인 탐색 가능
- 테이블 금액은 우측 정렬
- 날짜 표시는 YYYY-MM-DD
- 텍스트와 배경의 대비 확보
- 불필요한 애니메이션 최소화
- 반응형 크기에서 겹침이나 잘림 방지

## 13. 완료 기준

다음 항목을 확인할 수 있어야 한다.

- Sidebar 접기/펼치기 정상 동작
- 업무 탭 중복 생성 방지
- 업무 탭 전환 시 상태 유지
- 미저장 탭 닫기 경고
- 회사 전환 시 확인 처리
- 재접속 후 업무 탭 복원
- 상세 패널 열기/닫기 및 본문 너비 변경
- 테이블 기본/압축 전환 및 설정 유지
- 검색 팝업에서 키보드 선택
- 1920px, 1440px, 1366px, 1024px, 768px, 390px 너비에서 레이아웃 확인
- 빌드 및 기존 테스트 통과
- 기존 프로젝트 기능에 회귀 오류가 없는지 확인

테스트가 없는 기존 프로젝트라면 새로 구현한 핵심 상태 관리 동작에 대해 적절한 테스트를 추가한다.

## 14. 작업 원칙

1. 기존 코드를 분석한 후 필요한 변경 범위를 결정한다.
2. 공통 컴포넌트와 상태 관리 구조를 분리한다.
3. 화면별 중복 CSS 작성을 피한다.
4. 기존 파일을 불필요하게 삭제하거나 전체 재작성하지 않는다.
5. 실제 API가 없는 기능에는 샘플 데이터 사용 여부를 명확히 표시한다.
6. TypeScript를 사용하는 프로젝트라면 타입 안정성을 유지한다.
7. 구현 완료 후 변경 파일, 주요 컴포넌트, 테스트 결과, 미구현 사항을 정리한다.
8. 디자인 참고 이미지와 실제 렌더링 결과의 차이를 검토한다.

**최종 목표: 앞으로 새로운 업무 화면을 추가할 때 AppShell과 공통 UI를 그대로 재사용하고, 업무 페이지 콘텐츠만 구현하면 되는 상태를 만드는 것이다.**
