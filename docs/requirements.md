# 공통 UI v1

## 2026-11-13 Supabase 관리자 로그인

- 이 절은 이전 Mock 로그인 요구사항을 대체한다. 기존 Supabase Auth 이메일·비밀번호 계정으로 로그인한다.
- Fastify는 Supabase Auth 사용자 조회로 Bearer 토큰을 검증하고, public.users의 ACTIVE/미삭제/잠금 해제와 서버 지정 사무소의 ACTIVE OWNER 또는 ADMIN 소속을 요청마다 확인한다.
- 소속과 계정을 자동 생성하지 않는다. 회사 범위는 기존 서버 설정을 유지하며 클라이언트 회사 ID를 신뢰하지 않는다.
- 로그인 유지 선택 시 localStorage, 미선택 시 sessionStorage에 SDK 세션을 저장한다. 비밀번호는 저장하지 않는다. SDK 토큰 갱신과 로그아웃을 사용한다.
- 회원가입과 비밀번호 찾기는 여전히 명시적인 화면 체험용이다. 실제 가입·메일 발송은 후속 범위다.
- 운영 배포는 이번 범위가 아니다. 기존 로컬 접근 제한을 유지한다. pagesPreview는 UI 미리보기만 우회하며 백엔드 권한을 우회하지 않는다.
- 원격 읽기 확인: users 1명, ACTIVE 1명, office_members 0행. 006_existing_admin_membership.sql은 검토용으로 준비했으며 미실행이다.

## 2026-11-13 원지 정보 DB 표시

- `/company`는 서버가 지정한 원지 사무소 `tax_offices` 정보를 읽어 표시한다. 상단 데모 회사 선택과 무관하다.
- 법인등록번호, 기본/대표자/사업장/세무/메모와 검토일시를 매핑한다. 조회 실패 시 재시도를 제공한다.
- 수정값과 검토 체크는 열린 탭에서만 유지한다. DB 쓰기, 실제 Auth 로그인 연동은 이번 범위가 아니다.

## 2026-11-13 업무 메뉴 및 화면 배치

- 기초정보관리(기본 접힘)와 전표관리(기본 펼침)를 분리한다. 메뉴 상세 및 구현 범위는 [메뉴·레이아웃 적용 기록](menu-layout.md)을 따른다.
- 회사등록과 환경등록은 수집 정보 검토를 위해 모든 분야와 입력항목을 한 열로 세로 나열한다. 분야별 검토 확인을 제공하고, 확인 후 값을 수정하면 재검토 필요로 표시한다. 계정과목 및 적요관리는 기존 탭 구분을 유지한다.
- 회사등록과 환경등록 입력은 탭 메모리 시안이며 DB 저장하지 않는다. 편집 시 미저장 상태를 표시하고 페이지 이동·탭 닫기·회사 전환 보호를 적용한다.
- 최초 설정 안내는 대시보드의 선택적 진입 경로로 제공하며 매일 따라야 하는 순서로 강제하지 않는다.
- 기존 실제 매입매출 저장 계약, Mock 전표 및 수임업체 조회 경로를 유지한다.

- 저장·수정·삭제는 탭 메모리에서만 처리한다. 사용자별 패널 UI 설정만 브라우저에 저장한다.
- 범위·구조·검증·남은 제약: [전표 입력 Mock UI](voucher-ui.md).

## 2026-11-10 서비스 진입 UI 추가

- `/`는 서비스 랜딩, 기존 홈 대시보드는 `/dashboard`로 이동한다. 홈 탭 ID와 기존 업무 경로를 유지한다.
- `/login`, `/register`, `/forgot-password`는 프런트엔드 Mock 화면이며 실제 인증·회원 DB·메일 발송과 연결하지 않는다.
- UI 데모 계정·로그인 상태와 계정별 환경설정은 별도 브라우저 저장소에 보관한다. 아래 공통 UI v1의 입력값 저장 제외 원칙에 대한 이번 프로토타입의 명시적 예외이며, 업무 전표 저장 정책은 바꾸지 않는다.
- 비밀번호 원문을 저장하지 않는다. 실제 계정 보안 체계는 후속 구현이다.
- 구현 파일·동작·테스트·API 연결 지점: [서비스 진입 UI](entry-ui.md).

이번 작업의 기준은 [공통 UI 시스템 구현 지시서](ui-system-spec.md)이다.
기존 업무 분석은 [source-analysis.md](source-analysis.md)를 유지한다.

- Nuxt/Vue 기반 공통 작업 공간 레이아웃, 재사용 UI 컴포넌트, 홈·일반전표·거래처 데모 구현. 현재 구조는 [프런트엔드 아키텍처](frontend-architecture.md)를 따른다.
- 회사와 사용자는 명시적인 UI 데모 컨텍스트이며 서버 인증·권한으로 사용하지 않는다.
- 실제 전표 저장·분개 검증·신고·편집 그리드는 범위 밖이다.
- 재접속 복원은 사용자/회사별 탭과 활성 탭, 사용자별 밀도/사이드바 설정만 지원한다.
- 자유 입력 검색어·미저장 전표·선택 거래처는 저장하지 않는다.
- 구현·검증 기록: [ui-system.md](ui-system.md).

## 2026-11-10 매입매출전표 입력

이 절은 위 공통 UI v1의 전표 저장 제외 범위를 매입매출전표에 한해 확장한다.

- 회계관리 → 매입매출전표입력(`/sales-journal`). 기존 `/sales`는 유지한다.
- 사용자 확인: 해솔문구 본점, 2026.01.01~12.31. 회사·사업장은 서버 개발 인증 컨텍스트에서 고정하며 상단 UI 샘플 회사 선택을 권한으로 사용하지 않는다.
- 실제 PostgreSQL 등록·조회·수정·삭제. 저장은 `draft`이며 차대 일치가 필수다. `posted` 또는 `closed` 회계기간은 수정·삭제 불가.
- 거래유형 11(매출 과세), 51(매입 과세)만 지원. 부가세 0원은 확인요망이며 명시적 확인 후 저장한다. 공급가액·부가세·유형 변경 시 UI 확인 체크를 초기화한다.
- 거래처와 계정과목은 회사별 DB 마스터에서 선택한다. 미등록 거래처 생성, 세액 자동산출, 자동분개, 확정 및 신고 연결은 미구현이다.
- 전표 목록, 기간·유형·문자 검색, 조회 합계, 하단 분개 편집, F2 거래처 검색, 삭제/미저장 변경 확인을 제공한다.
- 금액은 15자리 이내 비음수 정수 문자열이며 분개 행은 양수다. BigInt로 계산하고 DB numeric으로 저장한다.
- 미저장 내용은 탭 메모리에만 유지한다. 저장 데이터는 새로고침 후 재조회된다.
- 검증 및 남은 제한: [매입매출전표 구현 기록](sales-journal.md).
