# SelfBooks 원본 자료 분석

2주 MVP의 범위는 일반전표와 매입매출전표의 입력·조회·저장·수정·삭제에 필요한 요구사항이다. 전표를 처리하는 데 필요한 기초정보 조회와 검증을 포함한다. 외부 수집, 전자세금계산서 연동, 장부, 신고서, 대시보드 구현은 이번 분석에서 후속 연동으로 분리했다. 자동분개와 사용자 설정의 첫 배포 범위는 확인 필요다.

## 향후 부가세 신고서 연결

- 과세기간별 공급가액·세액·건수 집계와 원전표 상세 확인을 위해 전표 식별자, 날짜, 거래처, 유형, 금액의 추적 경로를 고려한다. 일반과세 신고서는 11을 세금계산서 발급분, 17·22를 카드·현금영수증 발행분, 14 등을 기타 매출, 51을 일반매입 또는 고정자산매입의 데이터 출처로 참조한다. 고정자산 식별 기준은 확인 필요다. 간이과세 신고서도 매입매출전표 집계를 참조한다. (H 일반과세 신고서 11·13~15·21·23행, 간이과세 신고서 12~13행, E 118행)
- 공급가액·세액과 카드 발행금액집계표의 공급대가를 구분할 수 있어야 한다. 신고서 수기 수정값과 원천 집계값을 분리해 비교하며 불일치를 표시한다. 신고서 수정이 원천 집계표를 바꾸는 규칙은 적용하지 않는다. (H 공통규칙 5·11행, 발행금액집계표 2·9행)
- 현금매출명세는 현금영수증 미발행분도 불러오고 전표 집계와 신고 입력을 별도로 비교한다. 의제매입 명세는 환경등록과 지정 적요의 전표를 참조한다. 각 대상의 판정 및 매핑 기준은 후속 확인이 필요하다. (H 일반_부속명세 59·68·100·102행, E 148행, G 7553행 이후)
- 신고 마감과 전표 수정 제한의 관계는 확인 필요다. 현재 마감 연동은 일반 신고서에서 부속명세에 보내는 브라우저 메시지로 시연된다. (G 6행, E 118행 `vat-set-closed`)

## 누락되거나 모순된 요구사항

- **확인 필요**. A §9의 설정 화면 계정코드와 F2 샘플 코드가 불일치한다. 운영 계정과목 마스터와 거래유형별 분개 매핑이 필요하다.
- **확인 필요**. C p.1~3과 D는 라이트·블루를 제시하고, A §3은 테마 변경, G 17행 이후 신고 목업은 다크 기본·골드 강조를 사용한다. 전표 화면과 후속 신고 화면의 디자인 적용 범위를 정해야 한다.
- **확인 필요**. C p.5에는 전표번호가 있고 D 우측 전표 입력 그림에는 번호 입력칸이 보이지 않는다. 화면 노출·자동 부여·검색 정책이 필요하다. D에는 상단 적요와 행 적요가 함께 있다. 두 값의 관계는 미정이다.
- **확인 필요**. A §4의 2024·2026 예시로는 실제 회사의 조회 가능 회계기간을 확정할 수 없다.
- **확인 필요**. A §7의 전표 세액 자동 변경과 H 일반과세 신고서 21행의 매입세액 수기 처리 설명은 적용 화면이 다르다. 전표에서 어떤 유형을 자동 계산하고 수기 입력을 언제 허용하는지 별도 기준이 필요하다.
- **확인 필요**. H의 ‘확인필요’ 시트와 집계표의 ※ 표기는 신고 쪽 미확정 설계다. 수령명세서의 유형 번호(‘확인필요’ 4행)는 전표 거래유형으로 채택할 근거가 없다.

1. **화면과 필수값** — 최신 일반전표·매입매출전표 실행 시안과 주석을 받을 수 있는가? 전표번호 발급 단위, 행/헤더의 거래처·적요, 필수 필드와 편집 가능 필드는 무엇인가? (G1·S1)
