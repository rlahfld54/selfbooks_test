\# 셀프북스 화면 개발 주석 및 업무 로직 정리



\## 1. 전체 화면 구성 및 개발 방향



첨부된 셀프북스 화면 자료는 총 26개의 화면으로 구성되어 있으며, 기초정보 관리, 자료수집, 전표처리, 세무관리, 자산관리, 거래처 및 기초관리, 재무제표, 결산, 원장 및 신고 관련 기능으로 구분된다. 각 화면은 회계 업무의 흐름에 맞춰 구성되어 있으며, 사용자가 기초정보를 등록하고 자료를 수집한 뒤 전표를 생성하고, 결산 및 재무제표를 확인할 수 있도록 설계되어 있다.



현재 자료는 화면 UI를 중심으로 구성된 개발용 시안이다. 일부 버튼과 기능에는 JavaScript를 활용한 동작이 포함되어 있지만, 모든 기능이 실제 데이터베이스나 서버와 연동되어 완성된 상태는 아니다. 따라서 화면에서 확인되는 동작과 실제 서비스에 적용하기 위해 추가 개발이 필요한 부분을 구분해서 이해해야 한다.



\## 2. 개발자 주석 및 화면 내 표시 방식



화면에는 개발자가 확인해야 할 사항을 별도로 표시할 수 있도록 주석 기능이 구성되어 있다. 주석 내용은 `ANNOT\_TEXT`에 저장되며, 화면 요소에 지정된 `data-annot` 속성을 통해 해당 요소와 연결된다. `devToggleAnnot()` 함수는 주석 표시 기능을 켜거나 끄는 역할을 하고, `devJumpToAnnot()` 함수는 특정 주석이 연결된 화면 요소로 이동하거나 해당 요소를 강조하는 기능을 담당한다.



주석은 화면 오른쪽에 표시되는 `devAnnotDock` 영역을 통해 확인할 수 있으며, 변경 이력은 `devShowChangelog()` 함수를 통해 확인하도록 구성되어 있다. 이를 통해 개발자는 화면을 일일이 확인하지 않고도 해당 기능에 대한 설명이나 수정 요청 사항을 파악할 수 있다.



주석에는 확정된 사항, 신규 추가된 사항, 수정된 사항, 변경 이력 등을 구분하는 표시가 사용된다. 이러한 표시는 개발 진행 과정에서 어떤 내용이 확정되었고 어떤 내용이 변경되었는지를 확인하기 위한 목적이다. 따라서 실제 개발 명세서를 작성할 때도 주석의 내용을 단순히 화면 설명으로만 보지 않고, 기능 요구사항과 변경 요청사항으로 구분해서 반영할 필요가 있다.



\## 3. 공통 화면 및 버튼 동작



각 화면의 상단에는 공통적으로 사용할 수 있는 기능 버튼이 배치되어 있다. 기본적으로 화면의 테마를 변경하는 기능, 인쇄 기능, 삭제 기능이 제공되며, 화면별로 필요한 특수 기능은 별도로 유지하도록 구성되어 있다. 일부 화면에서는 추가 기능이 제공되고, 일반전표입력 화면의 경우 더보기 기능이 마지막 순서에 배치되는 형태로 정리되어 있다.



인쇄 버튼은 `window.print()`를 호출하는 방식으로 구성되어 있다. 현재는 브라우저의 인쇄 기능을 실행하는 형태이므로, 실제 서비스에서는 인쇄할 영역과 출력 양식, 페이지 구분 등을 추가로 검토해야 한다. 삭제 버튼 역시 화면상에서 제공되는 기능과 실제 데이터 삭제 처리는 구분해야 한다. 실제 삭제 기능을 구현하려면 삭제 대상 데이터 확인, 사용자 권한 확인, 삭제 가능 여부 검증, 서버 및 데이터베이스 반영 등의 처리가 필요하다.



\## 4. 회계연도 및 날짜 이동 로직



회계연도 이동 기능은 이전 연도와 다음 연도로 이동할 수 있도록 구성되어 있으며, 현재 기준 연도인 2026년을 기준으로 미래 연도 이동에 제한을 두는 형태로 정리되어 있다. 연도 이동 시에는 화면에 표시되는 날짜와 자료 목록, 그리드의 연도 정보가 함께 변경되어야 한다.



이전 연도 또는 다음 연도로 이동할 때는 현재 선택된 연도를 기준으로 데이터를 다시 구성해야 하며, 허용된 범위를 벗어나는 경우에는 해당 이동 버튼을 비활성화해야 한다. 화면 주석에는 2024년과 2026년을 기준으로 한 이동 범위 및 표시 방식에 관한 내용도 포함되어 있다. 따라서 실제 구현 시에는 연도 이동 가능 범위와 버튼 활성화 조건을 명확히 정의하고, 화면에 표시되는 연도와 조회되는 데이터의 기준 연도가 서로 일치하도록 처리해야 한다.



\## 5. 그리드 및 목록 관리 로직



자료 목록이나 전표 입력 화면에서 사용하는 그리드는 사용자가 필요한 항목을 선택하고 순서를 변경할 수 있도록 구성되어 있다. 컬럼 표시 여부와 컬럼 순서는 사용자별로 설정할 수 있으며, 설정한 값은 저장되어 다음 로그인 이후에도 유지되는 것을 기준으로 한다.



그리드에서 Delete 키를 누르는 경우에는 현재 선택된 셀의 값만 삭제하는 것이 기본 동작이다. 행 전체나 전표 전체가 삭제되는 방식과는 구분해야 한다. 또한 필수 입력 항목이나 계산에 의해 자동으로 생성되는 항목, 잠금 처리된 항목 등은 임의로 삭제할 수 없도록 제한해야 한다. 실제 개발 시에는 셀의 수정 가능 여부를 확인한 후 삭제 동작을 수행하도록 처리하는 것이 필요하다.



\## 6. 자료수집과 전표 연결 로직



자료수집 화면에서는 수집된 자료를 확인하고, 해당 자료를 회계 전표와 연결하는 흐름을 제공한다. 수집된 자료와 전표는 `collectLinkId`를 기준으로 연결하는 구조가 언급되어 있다. 하나의 수집 자료가 여러 개의 전표 행과 연결될 수 있는 구조이므로, 자료와 전표가 반드시 1:1 관계라고 가정해서는 안 된다.



자료와 연결된 전표를 취소하거나 연결을 해제하는 경우에는 원본 수집 자료의 상태도 적절하게 복구되어야 한다. 예를 들어 전표 연결이 취소되었다면 해당 자료가 다시 미처리 상태로 표시되는 등 원래 업무 상태로 돌아갈 수 있어야 한다. 다만 이러한 처리는 실제 데이터베이스와 서버 간의 상태 동기화가 필요하므로, 현재 화면의 시안만으로 완전하게 구현되었다고 볼 수는 없다.



\## 7. 전표 자동 처리 및 거래처 연결 로직



전표 입력 화면에서는 거래 유형 코드를 선택하면 해당 코드에 따라 세금 계산, 합계 금액, 결제 방법 및 전표 미리보기 내용이 자동으로 변경되는 구조가 설명되어 있다. 거래 유형 코드는 11번부터 64번까지 사용되는 것으로 정리되어 있으며, 코드에 따라 매입 또는 매출 등의 거래 유형과 세무 처리 방식이 달라질 수 있다.



거래처 입력 기능에서는 거래처명을 입력하면 기존 거래처 정보를 검색하고, 일치하는 거래처가 있는 경우 해당 거래처를 자동으로 연결하도록 구성되어 있다. 기존 거래처가 없는 경우에는 신규 거래처를 생성하는 방식이 `autoRegisterPartner` 기능으로 설명되어 있다. 거래처 코드 조회나 입력 보조 기능은 F2 키를 활용하는 형태로 구성되어 있다.



이 기능을 실제로 구현할 때는 거래처명이 동일하거나 유사한 경우의 처리 기준이 필요하다. 기존 거래처를 자동으로 연결할지, 사용자에게 선택하도록 할지, 신규 거래처로 등록할지를 구분해야 한다. 또한 거래처 자동 생성 기능은 중복 등록을 방지할 수 있도록 사업자번호나 거래처 코드 등의 식별 기준과 함께 검토해야 한다.



\## 8. 부가세 검증 및 확인요망 표시 로직



부가세 검증과 관련해서는 과세 유형에 따른 세액 검증 기능이 주석으로 정리되어 있다. 매출 과세 유형 11번과 매입 과세 유형 51번에서 부가세가 0원으로 입력된 경우에는 확인이 필요한 데이터로 판단하여 파란색 표시와 '확인요망' 배지 또는 안내 메시지를 보여주는 방식이다.



영세율이나 면세 유형은 일반 과세 유형과 다른 조건으로 처리되므로, 부가세가 0원이라는 이유만으로 동일한 경고를 표시해서는 안 된다. 즉, 거래 유형과 과세 구분을 함께 확인한 후 경고 여부를 판단해야 한다.



`checkZeroVatWarnings()` 함수는 현재 화면의 그리드에 표시된 데이터를 확인하여 부가세가 0원인 항목을 찾아내는 방식으로 설명되어 있다. 주석에는 샘플 데이터 중 22건이 확인 대상에 해당한다는 내용도 포함되어 있다. 다만 실제 서비스에서는 화면에 표시된 문자열만 검사하는 방식보다 서버에서 관리하는 과세 유형과 부가세 금액을 기준으로 검증하는 것이 적절하다. 사용자가 확인을 완료했는지 여부도 별도의 상태값으로 저장해야 이후 재조회 시 확인 여부를 유지할 수 있다.



\## 9. 계정과목 및 설정 팝업 로직



계정과목 관련 설정 팝업에는 기본 계정과목 설정, 신용카드 설정, 서비스 수수료 사용 여부 등의 항목이 포함되어 있다. 일부 항목은 사용자 요청에 따라 삭제된 것으로 표시되어 있으므로, 실제 개발 시에는 최신 화면과 주석을 기준으로 구성해야 한다.



계정과목 코드는 화면에 표시된 예시 코드와 F2 코드 조회 화면의 샘플 코드가 서로 일치하지 않는 부분이 있는 것으로 정리되어 있다. 따라서 현재 상태에서는 두 코드 체계가 실제로 연결되었다고 판단하기 어렵다. 실제 구현 전에는 계정과목 코드의 기준 데이터와 조회 화면의 코드가 동일한 체계를 사용하는지 확인해야 한다.



설정 팝업의 확인 버튼은 현재 토스트 메시지를 보여주는 수준의 시안 동작으로 설명되어 있다. 실제로는 사용자가 변경한 설정값을 저장하고, 저장된 값이 이후 화면이나 전표 처리 과정에 반영되도록 데이터 연동이 필요하다.



\## 10. 실제 개발 시 추가로 필요한 사항



현재 자료에서 확인되는 기능 중 일부는 화면 시연을 위한 임시 동작으로 구성되어 있다. 따라서 버튼을 눌렀을 때 화면에 메시지가 나타나는 것과 실제 데이터가 저장되거나 변경되는 것은 구분해서 개발해야 한다.



특히 자료수집 데이터와 전표의 연결 및 해제, 전표 자동 생성과 세액 계산, 거래처 자동 등록, 부가세 검증 결과 저장, 사용자별 그리드 설정 저장, 계정과목 설정 저장 등은 실제 데이터베이스와 연결되어야 업무 기능으로 완성된다. 삭제나 수정 기능에는 사용자 권한 및 데이터 상태 검증도 필요하다.



또한 화면에 표시되는 데이터가 샘플인지 실제 데이터인지 구분하고, 각 기능의 입력값과 출력값, 처리 조건, 오류 발생 시 동작을 정의해야 한다. 현재 주석에 기재된 내용만으로 명확하게 확인되지 않는 부분은 임의로 업무 규칙을 확정하지 않고, 담당자 확인이 필요한 항목으로 남겨두는 것이 좋다.



\## 11. 종합 정리



셀프북스 화면 자료는 단순한 화면 디자인이 아니라, 회계 업무를 처리하기 위한 화면 구성과 일부 업무 로직, 개발 요청사항 및 변경 이력을 함께 담고 있는 개발 참고 자료이다. 화면별 기능을 이해하는 것도 중요하지만, 자료수집부터 전표 생성, 검증, 결산 및 재무제표 확인까지 이어지는 업무 흐름을 기준으로 기능 간의 연결 관계를 파악하는 것이 중요하다.



개발 시에는 화면에 표시된 주석을 기준으로 요구사항을 확인하되, 현재 구현된 기능과 향후 추가해야 할 기능을 구분해야 한다. 특히 화면에서 동작하는 것처럼 보이는 기능이라도 실제 데이터 저장이나 서버 연동이 되어 있지 않을 수 있으므로, 업무 로직을 구현하기 전에 데이터 처리 기준과 예외 조건을 명확하게 정리할 필요가 있다.
