# 전표 입력 Mock UI (2026-11-11)

## 진입과 범위

- `/journal`: 일반전표 입력. 기존 헤더·사이드바·탭·공통 상세 패널 사용.
- `/sales`: 매입매출 입력 Mock. 사이드바 매입매출관리 → 매입매출 입력 · Mock.
- `/sales-journal`: 기존 실제 DB 연결 화면을 그대로 유지. 이번 화면에서는 API/DB를 호출하지 않는다.
- Mock 저장은 현재 탭 메모리의 변경을 확정하고 미저장 표시를 해제한다. 새로고침·탭 닫기·회사 전환 후 거래 데이터는 초기화된다.

## 동작

- 셀 클릭 또는 F2/Space로 편집. Enter/Tab 다음 셀, Shift+Tab 이전 셀. 편집 중 방향키는 입력 커서를 이동하고, 탐색 상태의 방향키는 셀을 이동한다. Esc는 편집을 취소한다.
- 계정코드·거래처코드는 이름이 병기된 브라우저 검색 목록을 제공하며 미등록 코드는 반영하지 않는다. 명칭 컬럼은 읽기 전용이다.
- 금액은 15자리 이내 비음수 정수 문자열. 합계는 BigInt. 소수·음수·지수 표기는 거부하며 부가세 자동 산출은 없다.
- 일반전표 하단은 일자+전표번호로 묶은 분개와 차대 합계를 즉시 표시한다. 매입매출 하단은 Mock 파일의 독립적인 읽기 전용 분개 예시이며 상단 금액 변경에 따라 자동 생성/수정하지 않는다. 새 행에는 분개 예시가 없다.
- 선택 삭제는 확인창을 거친다. 같은 전표의 일부 행을 삭제하면 차대 불일치 확인 결과가 갱신된다.
- 패널 4개 탭은 선택 전표를 공유한다. 거래처/증빙 셀에서 관련 탭으로 전환하며 고정 시 자동 전환을 중단한다. 과거 거래 열람은 현재 행을 변경하지 않는다.
- 검증 결과 클릭은 관련 셀로 이동한다. 표시 기간을 해제해 대상 행을 노출한다. 증빙 연결 여부는 일반전표에서 편집 가능한 증빙 셀이 없으므로 첫 셀로 이동한다.
- 패널 기본 너비 340px, 조절 300~480px. 1024~1280px에서는 300px으로 축소하며 1023px 이하는 기존 공통 오버레이를 사용한다. 초기 좁은 화면에서는 패널을 닫는다.
- 패널 너비·열림·하단 접힘·고정은 `accounting-pro:vouchers:<사용자>:<모드>`에 UI 설정만 저장한다. 입력 데이터·선택 행은 저장하지 않는다. 기존 사용자별 밀도 설정도 적용한다.
- 모바일 640px 이하에서는 조회 중심으로 셀 편집과 행 추가/삭제 버튼을 제한하며 모든 컬럼은 가로 스크롤로 제공한다.

## 검증 및 한계

- 단위 테스트 32개: 정수 입력, 큰 금액 합계, 일자/번호 그룹, 차대 불일치, 누락/부가세 0 확인, 세션 및 기존 서비스 회귀.
- Chrome 브라우저: 셀 편집·취소·잘못된 금액, 키보드 이동, 행 추가/삭제/저장, 인사이트 탭·고정·너비·열고 닫기, 증빙/과거 거래, 하단 접기, 매입매출 합계, 390px 모바일 및 hydration.
- 기존 작업 공간 브라우저 회귀: 직접 접근·탭·뒤로/앞으로·미저장 경고·회사 전환·새로고침·API fixture·기존 페이지·갤러리.
- 실제 세법 검증, 실제 증빙 이미지/PDF 업로드, 서버 저장, 확정/마감, 세액 계산, 자동분개, 대량 행 가상화는 미구현. 증빙은 HTML 가상 문서다. E01~E04는 화면 전용 예시 코드다.

## API 연동 후속 작업

Mock 조회/저장 어댑터를 타입이 지정된 API 서비스로 교체한다. 서버에서 회사·회계기간·권한을 주입/검증하고, 금액·분개·상태 검증과 원자적 저장을 수행해야 한다. 서버 성공 응답 이후에만 미저장 상태를 해제하고 로딩/실패/재시도/동시 수정 충돌을 처리한다. 증빙 연결 및 과거 조회의 API 계약, 거래유형별 분개 정책은 별도 확정한다.
