# 계정과목 및 적요관리 UI 프로토타입

- 경로: 기존 /accounts. 공통 레이아웃과 메뉴는 유지한다.
- 구현: frontend/app/features/accounts/. 타입, 독립 fixture, 검증·필터 함수, 탭 세션 composable, 분류/목록/입력 컴포넌트를 분리했다.
- 40개 계정과목, 80개 적요. 자산/부채/자본/수익/비용과 각 하위 분류를 포함한다. 코드·성격·분류는 UI 예시이며 법정 계정체계로 사용하지 않는다.
- 계정과목 검색, 사용여부, 분류 필터, 모든 데이터 열 정렬, 표시 행 전체/개별 체크, 밀도, 내부 스크롤과 빈 결과를 지원한다.
- 기본/확장/연결적요 상세, 계정 추가/수정/취소, 적요 추가/수정/삭제, 전체 적요 검색과 복합 필터를 제공한다.
- 필수값/중복코드/분류/연결계정 검사는 UI 테스트용이다. 실제 회계 검증이나 DB 제약이 아니다.
- 변경은 탭 객체에 귀속된 Vue 메모리에만 반영한다. 새로고침 시 초기화한다. 기본 불러오기와 화면 새로고침은 확인 후 Mock 전체를 초기화한다.
- 미저장 폼은 화면 내 전환/닫기/취소 시 확인한다. 공통 setDirty로 기존 페이지 이동·회사 전환·탭 닫기·브라우저 종료 보호에 연결한다.
- 좁은 화면의 상세 패널은 목록 위에 표시되며 닫기 버튼으로 목록에 복귀한다. 표는 자체 가로 스크롤을 사용한다.
- Nuxt UI가 프로젝트에 설치되어 있지 않아 기존 UiButton/UiInput/UiSelect/UiModal/ConfirmDialog/PageToolbar를 재사용했다. 라이브러리 추가와 새 Nuxt API 도입은 없다.
- DB, 백엔드, Supabase, API, 영구 저장, 기존 전표용 Mock 데이터에는 변경이 없다.
- frontend/tests/accounts.test.ts에 fixture 독립성, 복합 필터, 정상 편집 및 필수/중복/분류/연결계정 예외 테스트를 작성했다.
- 테스트·타입 검사·빌드·DB 통합·브라우저/E2E: **미실행 — 사용자 요청 시 실행**.
- 남은 확인: 설치 환경에서 타입 및 반응형/키보드/모달 동작 확인. 확장정보와 실계정 업무 규칙은 추후 계약 확정 필요.

## 2026-11-18 실제 기본 계정과목 조회 (앞의 Mock 계정 조회 정책 대체)
- 사용자 승인으로 public.fi_account_default 조회만 연결했다. GET /api/account-defaults는 기존 인증·로컬 접근 제한을 사용하고 읽기 전용 트랜잭션으로 deleted_at IS NULL 행을 조회한다. 정책 우회 시 조회를 거부한다.
- 해당 테이블에는 회사/사무소 컬럼이 없는 공통 기본 마스터다. 요청에서 회사 ID를 받지 않는다. 스키마 변경 및 쓰기 API는 없다.
- 최초 진입, 기본 계정과목 불러오기, 새로고침은 실제 조회한다. 탭을 다시 열 때 이미 불러온 메모리 변경은 유지한다. 오류 시 Mock으로 대체하지 않고 오류/재시도를 표시하며 이전 목록을 유지한다.
- bigint 원본 ID는 문자열로 보존하며 UI 식별자와 분리한다. 출력용 명칭은 별도 컬럼이 없어 계정과목명으로 초기화한다.
- 사용자가 확인한 대분류: 1 자산, 2 부채, 3 자본, 4 수익, 5 비용, SPECIAL 특수설정계정과목. 중분류는 조회 원문을 사용해 트리를 확장한다.
- 외화 처리 코드는 의미를 추측하지 않고 원문을 표시한다. 영어명·표준재무제표코드·세부속성·관계계정·차량 여부를 실제 컬럼에 매핑한다.
- 실제 계정에 Mock 적요를 자동 연결하지 않는다. 적요 추가 및 모든 편집은 탭 메모리에서만 처리한다. 공개 Pages 미리보기는 기존 Mock을 유지하며 API를 호출하지 않는다.
- 실제 테이블 컬럼/제약/예시 3행/분류별 집계의 읽기 전용 확인 완료. 이는 테스트 실행이 아니다.
- 정상 조회·인증 거부·조회 오류·정책 우회·bigint·코드 매핑 테스트 코드를 추가했다.
- 단위 테스트·타입 검사·빌드·DB 통합·브라우저/E2E: **미실행 — 사용자 요청 시 실행**.

## 수임업체 적요 조회 연결
- GET /api/account-summaries는 서버 고정 네네치킨 청라1호점 UUID와 인증된 officeId를 함께 검사한다. 요청에서 업체 ID를 받지 않는다.
- fi_summary와 fi_account를 client_id/account_id로 조인하고 삭제 행을 제외한다. 기존 인증, 읽기 전용 트랜잭션, 정책 우회 거부를 유지한다.
- 적요 전체관리는 실제 적요와 회사별 계정명을 표시한다. 기본 계정과목 목록은 기존 fi_account_default 조회를 유지한다.
- 원본 기본계정 ID로 연결적요를 연결하며 기본 원본 없는 계정도 적요 전체관리에서 누락하지 않는다.
- 차변/대변은 UNKNOWN(미확정)으로 표시한다. transaction_element_code는 원문 숫자, summary_type_code는 FIXED만 고정으로 표시하고 다른 값은 원문을 표시한다.
- 업체명·적요 조회 실패·재시도를 제공한다. 기존 편집은 메모리 전용이며 DB 쓰기를 추가하지 않는다.
- 정상 매핑/빈 목록/원본 없는 계정/미확정 성격/사무소 범위/조회 오류 테스트 코드 작성.
- 테스트·타입 검사·빌드·DB 통합·브라우저/E2E: 미실행 — 사용자 요청 시 실행.
